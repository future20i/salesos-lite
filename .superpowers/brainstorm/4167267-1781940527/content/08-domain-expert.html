🔍 领域专家视角：项目型外贸销售的实战匹配

以一个做了15年工业设备外贸的老兵视角，审视这个系统能不能活过第一个客户

问题 1：商机阶段划分漏了最关键的「技术交流」

我们之前定的五个阶段：

线索验证 → 需求确认 → 报价/谈判 → 合同 → 成交

对于项目型销售，中间的「技术交流」是整个周期里最耗时的环节——方案评审、现场考察、技术答辩、参数确认。这是跟贸易型最大的区别。

贸易型：客户说要报价 → 你发报价 → 谈价格 → 成交。技术交流几乎不存在。
项目型：客户说要方案 → 你做方案 → 客户提问题 → 你去现场答辩 → 改方案 → 再审 → 做样机测试 → 再审 → 报价 → 再谈。

建议修正：
线索验证 → 需求确认 → 技术交流 → 报价/谈判 → 合同 → 成交

而且「技术交流」阶段要能容纳多个子环节——不是一步完成的。

问题 2：决策链不是一条线，是一张网

Opportunity 模型里有一个 decision_maker 字段。实战中，项目型销售的决策链是：

• 技术负责人（提需求、审方案、做技术判断）— 他是「守门员」
• 采购负责人（比价、谈合同、管流程）— 他是「执行者」
• 最终决策人（老板/副总裁）— 他是「拨款人」

关键：这三个人关心的东西完全不同。你跟技术聊参数，跟采购聊交期，跟老板聊 ROI。同一个人不能同时应对这三种沟通。

建议：
decision_maker 改成 decision_chain: JSON 数组——
[{role: "技术负责人", name: "张总", concerns: "响应时间<5ms"}，
{role: "采购", name: "李经理", concerns: "交期+付款条件"}，
{role: "最终决策", name: "王总", concerns: "总成本+服务"}]

跟进项可以关联到决策链中的具体角色。这样 AI 起草消息时知道对谁说、说什么。

问题 3：缺失「竞争对手」的跟踪

项目型销售的竞品信息极其重要——而且是动态的。客户可能同时跟 3 家供应商在谈， 不同阶段有不同的竞品在比。

Opportunity 模型目前只有 competitor 字段（一个字符串）。实战中：
• 技术交流阶段：客户说"XX 品牌说他们能做到 3ms"
• 报价阶段：客户说"XX 比你便宜 15%"
• 谈判阶段：客户说"XX 提供 5 年免费维保"

这些竞品信号散落在对话里，但系统应该追踪。不是只记录「竞争对手是西门子」，而是记录「什么时候客户提到了什么竞品、说了什么、我们怎么应对的」。

建议：
competitor 字段改成 competitor_tracking: JSON 数组——
[{name: "某进口品牌", mentioned_at: "6/15", context: "客户说他们能做到3ms",
our_response: "发技术对比文档，说明飞轮vs超级电容的优势"}]

这是 AI 诊断沉默原因的关键输入——客户沉默了是不是因为竞品在压价？

问题 4：报价不是一张纸，是一轮谈判

贸易型的报价通常是「客户问价→你报→成交或流失」。项目型是多轮报价：

初版方案（技术参数+粗略预算）→ 详细方案（分项报价）→ 最终报价（含商务条款）→ 合同

中间的每次报价调整都有原因——"客户要求交期从 45 天压缩到 30 天，所以加了加急费"。
