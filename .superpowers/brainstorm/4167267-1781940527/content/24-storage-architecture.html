人脉画像的存储架构

不是所有东西都进数据库。SQL 存结构，JSON 存叙述，AI 在读取时生成洞察。

PostgreSQL
结构化
第一层：关系型数据 — PostgreSQL 标准列
需要查询、筛选、索引、关联的数据。这是数据库最擅长的事。
规则：能用一个 SQL WHERE 查出来的，放 PostgreSQL 列。
数据列类型示例
姓名、公司、职位VARCHAR张建国 · 台达电子 · 技术总监
生日DATE1972-03-15（用于日历提醒）
关系深度评分SMALLINT7（用于排序和筛选）
最后互动时间TIMESTAMP用于沉默检测
标签TEXT[]{'技术型','champion','老客户'}
权限UUIDcreated_by, access_list
关联FKlead_id, opportunity_id, tenant_id
PostgreSQL · 标准索引 · RLS 行级安全
PostgreSQL
JSONB
第二层：叙述型数据 — PostgreSQL JSONB 列
有结构但不需要单独索引的复合数据。比如决策链上的三个人，每个人有不同的关注点。
规则：结构会变、内容因人而异、不参与 SQL 筛选的，放 JSONB。
数据原因用 JSONB 而非列
家庭信息配偶/子女/父母的数量不固定，结构因人而异
兴趣爱好[{category:"运动", detail:"高尔夫差点12", note:"..."}] — 条目数不固定
教育/职业背景多段经历，每段结构相同但段数不定
决策链成员[{role, name, concerns, stance}] — 每个商机人数不同
资源网络[{name, relationship, expertise, closeness}] — 条目数可变
PostgreSQL JSONB · GIN 索引（如需搜索）· 不参与 RLS（在应用层过滤）
加密存储
端到端
第三层：敏感叙述 — 端到端加密存储
核心驱动力和影响力杠杆的信息。服务端存储的是密文。只有创建者的客户端可以解密。
规则：如果泄露会导致信任崩塌的数据，端到端加密。服务端永不见明文。
数据加密原因
核心恐惧"技术选型失误背责。上次差点被问责。" — 被老板看到，张总业务关系终结
核心野心"想升VP，需要这个项目证明自己" — 被同事看到，内部政治风险
组织处境"新副总倾向竞品，他在替我们打仗" — 泄露则暴露内部分裂
影响力杠杆"女儿需要实习机会，我们有清华CTO关系" — 被公开则变成利益交换
资源匹配记录"帮张总妈妈安排了心外科手术" — 外部看到则变成腐败证据
客户端加密 · 创建者私钥 · 服务端存密文 · 解密仅在客户端
AI 生成
不存储
第四层：AI 洞察 — 读取时生成，不存储在数据库
这是最关键的设计决策。AI 的洞察不是数据，是分析结果。它应该在用户打开画像页面时实时生成——基于最新的原始数据 + 最新的对话记录 + 最新的上下文。

为什么不能存：
• 存下来的 AI 洞察会过时。三个月前的"他关心响应时间"今天可能已不适用
• 存下来的洞察会被当作"事实"而非"分析"。业务员不会质疑一条存在数据库里的 AI 输出
• 存下来的洞察失去了上下文。"AI 说他是 champion"——但基于什么说的？三周前的对话已经变了
• 存 = 固化。AI 洞察必须保持"液态"——每次都重新思考
AI 生成的内容什么时候生成存在哪
战前简报打开对话时不存 · 实时生成
策略卡（该做/忌做）起草回复时不存 · 实时生成
AI 人脉洞察打开画像页时不存 · 实时生成
反叙事（"如果全错了"）触发 B1 时缓存 24h · 不固化
话术建议（这次该问什么）打开对话时不存 · 实时生成
LLM API 调用 · Prompt 拼接原始数据 · 输出不持久化 · 每次重新推理
事件日志
不可变
第五层：互动记录 — PostgreSQL 事件日志（不可变）
所有推理的原材料。对话摘要、观察记录、画像变更。只追加，不修改，不删除。
规则：这是 AI 推理的原始数据源。必须完整、不可变、可回溯。
数据类型存储方式用途
互动摘要PostgreSQL · 追加"2024年会聊了半小时音响"
对话关键信息PostgreSQL · 追加"张总提到新副总倾向进口品牌"
画像版本快照PostgreSQL · JSONB · 追加每次更新画像时存快照（v1→v2→v3...）
置信度变更记录PostgreSQL · 追加"预算没问题" 置信度: 中→低（李经理矛盾）
审计日志PostgreSQL · 追加谁、何时、访问了什么
PostgreSQL · INSERT-only · 不设 UPDATE/DELETE 权限 · 定期归档
🔑 总原则：

能查的存列。 需要 SQL WHERE / ORDER BY / JOIN 的数据 → PostgreSQL 标准列。
会变的存 JSONB。 结构不定、条目数不定的叙述数据 → PostgreSQL JSONB。
会致命的加密。 泄露即信任崩塌的 → 端到端加密，服务端存密文。
会过时的生成。 AI 洞察不存储。每次读取时基于最新原始数据实时生成。
要追溯的追加。 互动记录和画像变更 → 不可变日志，只 INSERT，不 UPDATE。
